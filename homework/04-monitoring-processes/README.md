# Заказ 04 — мониторинг процессов

Два способа проверки:
1. `telemetry_sample.csv` — искусственные замеры процессов во времени.
2. `python run_workers.py` — запускает два **безопасных** тестовых процесса.

Напишите свой монитор, который раз в 1–2 секунды записывает время, PID,
название/командную строку, CPU и RSS-память, отмечает превышения порога.
Не завершайте процессы системы; для опыта используйте только процессы из лаборатории.

В CSV есть одинаковые имена, разные PID, перезапуск и постепенный рост RSS.
Проверьте, что монитор не путает завершившийся процесс с новым экземпляром.
`run_workers.py` ограничен по времени и объёму памяти.

## Монитор

`monitor.py` — один файл, только стандартная библиотека Python (ничего
устанавливать не нужно).

Монитор раз в 1,5 с записывает: время, PID, имя, командную строку, CPU, RSS
и ΔRSS, отмечает превышения порогов `ПОРОГ RSS` / `ПОРОГ CPU`.
Завершившийся процесс закрывается отдельной записью, а новый PID с той же
командной строкой помечается как **перезапуск** — статистика старого и нового
экземпляра не смешивается.

## Как запустить в VS Code

1. Откройте папку проекта: **File → Open Folder… → `04-monitoring-processes`**.
2. Нажмите **F5** и выберите конфигурацию:
   - «1. CSV (telemetry_sample.csv)» — быстрый прогон по файлу замеров;
   - «2. Живые процессы (run_workers.py)» — реальный прогон на ~35 секунд
     (монитор сам запускает лабораторные процессы и сам их не трогает).
3. Либо в терминале VS Code:

```powershell
python monitor.py                          # прогон по telemetry_sample.csv
python monitor.py --live --rss-threshold 30  # живые процессы run_workers.py
```

Пороги при необходимости задаются флагами `--rss-threshold` (МБ) и
`--cpu-threshold` (проценты одного ядра). Период опроса — `--interval` (по
умолчанию 1,5 с).

## Результат

- в консоли — строки замеров, события запуска/завершения/перезапуска и
  превышения порогов;
- в конце — итог: сколько процессов, перезапусков и превышений;
- `monitor_log.csv` — журнал замеров рядом с `monitor.py`.
